# 后台验证与有限修复

工作台在创建流程后默认自动验证；保存默认参数、流程定义或确认聊天修改后也会重新验证。只修改中文名称不重跑，运行面板临时输入参数不触发额外验证。已有流程可在编辑面板点击“后台验证与修复”。修改后立即撤销旧的验证状态。

## 执行过程

1. 保存原定义和本次默认参数，生成一次固定验收条件。也可由 CLI 提供 checks JSON。
2. 在独立浏览器会话中执行脚本。生成、修改及修复验证默认使用真正的 headless，不显示窗口或任务栏图标；有验收条件时检查最终页面和下载文件。
3. 有固定验收条件且脚本通过后，使用另一独立会话执行 LLM 模式，并检查相同条件；无验收条件的试运行不重复执行 LLM 模式。
4. 失败时保留工具结果、最终观察与验收失败信息，交给模型提出最小修复。诊断输入只含最近 10 个操作，并截断长文本。
5. 最多修复 2 次；有固定验收条件时，每次修改后两种模式必须重新验证同一个版本。修复不能改变原目标、入口、参数、默认值或文件权限，也不能修改验收条件。
6. 有固定验收条件时，双模式均通过才标为“双模式验证通过”。无法制定验收条件时执行脚本试运行；步骤完成后工作台可采用候选定义，但保持“待验证”，不宣称业务成功。失败保留原版及诊断；CLI 不覆盖传入文件。

脚本失败时先修复，不立即再跑 LLM 模式。固定验收失败不能由模型的 `finish/succeeded` 覆盖。模型验收格式无效时，执行前最多纠正一次，并在 `report.json` 的 `contract_attempts` 中保存原始响应、错误及归一化条件。

默认情况下，无法制定验收条件或格式纠正失败会进入固定步骤试运行：只执行脚本，不进行 LLM 重复执行；成功报告 `executed`，说明“业务结果未核验”。传入的 checks 文件无效时仍拒绝执行。缺少参数、登录凭据等准备错误报告 `not_started`，不当作网页执行失败。

| 报告状态        | 含义                                       |
| --------------- | ------------------------------------------ |
| `passed`      | 同一版流程的脚本与 LLM 均通过固定验收      |
| `executed`    | 无独立业务验收条件，固定步骤已执行完成     |
| `blocked`     | 实际执行或验收未通过，或触及预算与权限边界 |
| `not_started` | 准备阶段中止，尚未执行网页                 |

## 全部授权与文件

验证固定使用 `allow`，按用户要求全部授权，不弹出人工或 AI 审核。普通运行保留原有三种授权选择。独立浏览器会话没有用户原浏览器的 Cookie，不复用 profile；这属于浏览器与文件隔离，不是虚拟机或操作系统权限沙箱，不能撤销网站上的真实提交。

上传只复制本次已选择的文件，使用副本；下载放在每一版、每一种模式的独立目录。不同运行互不覆盖。文件验收检查数量、非空/最低字节数，并记录 SHA-256。

默认允许文件操作，每个修复版本的上传/下载调用预算为该版流程文件步骤数的两倍，为脚本及 LLM 各一次预留。预算在失败时也会消耗，避免超时后重复传输。修复进入下一版本时重新分配额度；当前版本重复调用超限时停止，并明确说明是次数限制而非下载权限不足，不静默跳过，也不将旧下载或模拟上传当作新执行成功。需要更多重复验证时由用户另行发起；工作台可取消勾选文件许可，CLI 可使用 `--no-allow-files`。

最多 30 个操作/模式、0–3 次可配置修复（默认 2）、15 分钟协作式预算；取消和时间预算在操作边界检查，进行中的模型请求或工具等待结束后停止，不是强制中断进程。模型请求有独立超时。界面可点击“停止验证”。

## 命令行

```powershell
.\.venv\Scripts\python -m browser_skill_agent validate skills/element_cn_collapse/SKILL.md
```

需要 `.env` 模型配置。即使脚本重放不调用决策模型，制定验收条件、修复和 LLM 模式会消耗 Token。最终报告统计整个验证过程的服务端用量，不估算费用。

可选：`--checks checks.json`、`--max-repairs 0`、`--no-allow-files`、`--output data/validations`。CLI 默认读取 Skill 同目录的 `example_params.json`，显式参数覆盖示例值。

固定验收示例（仅在最终现场检查，不执行业务操作）：

```json
[
  {"title":"查询结果正确","kind":"page","args":{"target":{"id":"result"},"state":"text","value":"查询完成：人工智能 / 教程","timeout":10}},
  {"title":"下载完成","kind":"download","name":"result.txt","count":1,"min_bytes":1}
]
```

页面检查支持 visible、hidden、text、value、count 及 URL；属性或精确值使用 `kind=read`、原工具读取 args 和 `equals` 验收，例如 aria-selected 等于字符串 true。可使用 `page_url` 选择唯一结果标签页。暂不支持中途消失的证据、跨执行文件缓存或任意业务断言代码。登录使用流程配置或人工接管，见[登录说明](login.md)。

## 报告与边界

`data/validations/<时间-编号>/` 保存 original.md、各 revision-N.md、checks.json、report.json、隔离文件及通过后的 SKILL.md。报告包含每次实际工具调用、结果、观察、验收证据、修复说明、参数和用量，属于本地数据，受 .gitignore 排除。

“双模式验证通过”仅覆盖该版本、该组参数和固定验收条件。自动生成的验收条件本身仍可能不完整；不能据此保证任意参数、后续网站改版或全部业务语义都正确。对高要求流程应提供明确 checks，并使用测试账户或测试站点。

## 开发验证

```powershell
.\.venv\Scripts\python tests/sandbox.py
.\.venv\Scripts\python tests/studio_validation.py
# 下项会请求真实模型；使用本地人工构造的中文动态页面及测试输入
.\.venv\Scripts\python tests/sandbox.py --live
```

本地测试覆盖定位修复、动态等待、下拉精确匹配、两种模式、模型虚假完成、文件复制与下载、文件次数上限，以及创建/参数修改/聊天修改后自动验证。真实端到端测试包含实际录制、模型生成、模型执行及固定结果验收。

本次端到端结果与用量见[历史测评记录](sandbox-validation.md)。

验证仍使用全部授权，支持上传、下载及已配置的账号密码自动登录。遇到验证码或扫码等人工登录时停止并保留诊断，不等待不可见窗口中的操作。需要人工接管时，可通过验证命令添加 `--headed` 使用有窗口模式；普通流程运行的显示设置不变。
